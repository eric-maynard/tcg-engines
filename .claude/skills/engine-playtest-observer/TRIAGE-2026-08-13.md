## 5. Top 3 themes worth attacking next

**1. Land-loss, not bug-fixing, is now the biggest leak.** Seven `done/` items and one 08-12 marker
flip did not survive to HEAD, and one landed flip has been re-marked in the shared tree. That is
more lost work in one day than any single engine cluster below. Two concrete asks: (i) a lane must
not close an item until `land-patch.sh` reports `committed=true` for the files that carry the fix —
a green local run is not a land; (ii) a cheap post-land audit (`for each done item with a repro:
does its marker still exist at HEAD?`) belongs in the periodic loop — it found all seven of these in
one query and would have found them the same day.

**2. The whole-file land model quietly reverts other lanes.** `72b0d41a5936`'s `play-options.ts`
fix is simply absent from HEAD with no failure recorded anywhere, and three queue items were failed
this round purely because a shared file carried another lane's in-flight hunks. `stale-base-check.py`
catches the bulk-revert case; it does not catch a small landed hunk being dropped. Worth extending
the check to "does this incoming file still contain every hunk any landed commit added to it", or
moving to a real 3-way apply.

**3. Multi-instance resolution is the only large engine capability left in the parked pile.**
After the Make-Choices step and play-time slots landed, the moonfall / Deceiver / naming cluster is
retryable and the remaining capability gap is a single one: *the engine cannot pause inside a
resolving item or inside `awardPoints` and come back* — `36d3e76275bf` + `f82c89cb355d` (703 static
recount between damage instances), `3948e2aa07ac` (372.1 ordering), `b639ddae9a1e` (Burn Out
431.2.c), and 4 live markers (Piercing Light × Counter Strike ×3, Boss buff recount). One
capability, ~7 facets — the best-value engine project on the board.
